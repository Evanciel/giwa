# 화면 편집기 (보이는 대로 끌어다 놓기) 계획·설계

> ADR-0138. 관리 화면 `/admin/editor`. Wix 편집기처럼 실제 사이트 화면 위에서 블록을 더하고, 옮기고,
> 고르고, 고친다. 서비스는 위젯(`widgets`)과 변경 묶음(`changesets`)을 그대로 쓴다.

## 1. Wix 편집기 분석

Wix 고객센터 문서에서 확인한 것만 적는다(2026-11-08).

| Wix 기능 | 어떻게 동작하나 | 출처 |
|---|---|---|
| 섹션 더하기 | 왼쪽 「Add Section」 판에서 빈 섹션이나 미리 꾸민 섹션을 종류별로 골라 페이지로 끌어다 놓는다 | support.wix.com `adding-a-strip` |
| 띠(Strip) | 화면 폭 전체를 차지하는 가로 띠. 안에 요소를 담는다 | 같은 문서 |
| 층(Layers) 판 | 페이지의 요소를 나무 모양으로 보이고, 끌어서 순서를 바꾸고, 눈 단추로 숨긴다 | `using-the-layers-panel` |
| 고르기와 떠 있는 도구막대 | 요소를 누르면 테두리와 작은 막대(설정·디자인·순서·복제·지우기)가 뜬다 | `using-the-editor-tools` |
| 검사기(Inspector) | 오른쪽 판에 고른 요소의 디자인·움직임·설정 탭 | `studio-two-editor-working-with-the-inspector-panel` |
| 기기 전환 | 데스크톱(1001px~)·태블릿(751~1000)·휴대폰(320~750) 폭으로 보고 고친다 | `studio-editor-designing-across-breakpoints` |
| 휴대폰에서만 숨기기 | 지우지 않고 그 기기에서만 숨김. 「숨긴 요소」 판에서 되살린다 | `wix-editor-hidden-elements-in-the-mobile-editor` |
| 되돌리기·다시 하기 | Ctrl+Z / Ctrl+Y, 위 막대 화살표 | `wix-editor-using-undo-and-redo` |
| 저장과 발행 | Ctrl+S 는 저장만, 발행은 따로. 사이트 기록(Site History)에서 이전 판으로 돌아간다 | `wix-editor-keyboard-shortcuts-in-the-editor`, `using-the-editor-top-bar` |
| 자유 배치 | 요소를 픽셀 단위로 아무 데나 놓고 눈금·안내선(5px 붙음)으로 맞춘다 | `using-the-editor-tools` |

## 2. 우리 구조에 옮기기

| Wix | Maru | 판단 |
|---|---|---|
| 섹션·띠 | 섹션 블록(hero·features·stats… ADR-0125)과 위젯 | 그대로 맞는다. 블록이 곧 띠다 |
| Add Section 판 | 「더하기」 판: 위젯 종류를 묶음(첫 인상·소개·글 목록·사진·연락·광고)별 카드로 | 만든다 |
| 끌어다 놓기 | 화면 안 블록 사이와 빈 자리 위로 끌어 놓는다. 놓을 곳은 가로줄로 보인다 | 만든다 |
| 층 판 | 「층」 판: 자리(머리글 아래·큰 배너·본문·오른쪽 곁·바닥글…)별 블록 목록, 끌어 옮기기, 눈 단추 | 만든다 |
| 고르기·도구막대 | 블록을 누르면 테두리와 막대(위로·아래로·복제·숨기기·지우기) | 만든다 |
| 검사기 | 오른쪽 판: 제목, 보이는 범위(이 화면만·모든 화면), 설정 칸(admin-ui.js 의 schema 폼 재사용) | 만든다 |
| 기기 전환 | 화면 폭을 1280·768·390 으로 바꿔 본다 | 만든다. 기기별 숨기기도 만든다(ADR-0146) |
| 되돌리기 | 편집기 안에서 Ctrl+Z / Ctrl+Y (초안 기록 50번) | 만든다 |
| 저장·발행·사이트 기록 | 「발행」 하면 변경 묶음 하나를 만들고 적용한다. 변경 묶음 화면에서 한 번에 되돌린다 | 원칙 4 와 그대로 맞는다 |
| 초안 저장 | 이 브라우저(localStorage)에 화면마다 초안을 둔다. 다시 열면 이어서 고칠지 묻는다 | 만든다 |
| 자유 배치 | 하지 않는다 | 한국형 홈페이지는 섹션을 쌓는다. 픽셀 배치는 휴대폰에서 깨지고(Wix 도 기기별로 다시 손봐야 한다) 접근성 순서가 어긋난다. Wix 의 새 편집기(Studio)·Squarespace 도 섹션 쌓기다 |
| 글자 바로 고치기 | 만든다(ADR-0144) | 고른 블록의 글자 칸을 한 번 더 누르면 그 자리에서 고친다. 마크다운 칸·조직도는 오른쪽 판에서 |
| 사이트 공통 부분 고르기 | 만든다(ADR-0145) | 사이트 이름·설명·위 메뉴·바로가기·아래 메뉴를 화면에서 누르거나 층 판에서 골라 고친다. 블록과 같은 변경 묶음으로 발행한다 |

## 3. 화면

```
┌ 위 막대: ← 관리 | 화면 [첫 화면 ▾] | [🖥 💻 📱] | ↶ ↷ | 고친 곳 3 | [발행] ┐
├ 왼쪽 판 ──────┬ 가운데: 실제 사이트 화면(iframe) ────────────┬ 오른쪽 판 ─────┤
│ [더하기][층]   │  ┌ 머리글 아래 ─────────── 여기에 놓기 ┐   │ 고른 블록       │
│ 첫 인상        │  │ [큰 배너 블록]  ← 누르면 테두리+막대  │   │ 제목 [      ]   │
│  ▣ 큰 배너     │  │ ─────── 놓을 곳 가로줄 ───────        │   │ 보이는 곳 (●)이 │
│  ▣ 숫자 띠     │  │ [최근 글 블록]                        │   │ 화면만 ( )모든  │
│ 글 목록        │  └───────────────────────────────────────┘   │ 설정 칸들…      │
│  ▣ 최근 글 …   │                                              │ [숨기기][지우기]│
└────────────────┴──────────────────────────────────────────────┴─────────────────┘
```

- 화면 고르기: 첫 화면, 공개된 페이지, 게시판.
- 왼쪽 판 「더하기」: 카드를 화면으로 끌거나, 누르면 지금 고른 블록 아래(없으면 본문 끝)에 들어간다.
- JS 가 없으면 편집기를 쓸 수 없다고 말하고 위젯 화면으로 안내한다.

## 4. 구조

1. **편집기 화면** `GET /admin/editor?screen=home|page:<주소>|board:<주소>`
   - 관리 화면 바깥 막대 없이 꽉 찬 화면. 자기 CSP(`frame-src 'self'` 를 더함)를 쓴다.
   - 위젯 전체 목록·종류·schema·화면 목록을 `<script type="application/json">` 으로 싣는다.
2. **캔버스** `GET|POST /admin/editor/frame?screen=…`
   - 로그인(디자인 권한)한 사람만. POST 는 CSRF 머리글(`x-csrf-token`)과 초안 JSON(위젯 전체 목록).
   - 공개 라우터에 쿠키 없는 GET 을 보내 실제 공개 화면을 그린다. 이때 `tokio::task_local!` 로 초안을
     건넨다. `widgets::regions` 는 초안이 있으면 DB 대신 초안 목록을 같은 규칙(`Screen::matches`·켜짐)으로
     고르고, 위젯 값에 `edit_id`, 템플릿 값에 `editing` 을 넣는다.
   - 기본 테마는 `editing` 일 때 위젯을 `data-maru-w` 로 감싸고, 머리글 아래·큰 배너·본문·바닥글은 비어 있어도
     `data-maru-region` 빈 자리를 그린다. 사본 통계·조회수는 세지 않는다(미리보기와 같은 방식).
   - 응답은 공개 CSP(`frame-ancestors 'self'`) 그대로. 광고 nonce 정책은 편집 중에는 걸지 않는다.
3. **편집기 JS** `/admin/assets/page-editor.js`
   - 캔버스는 같은 출처라 부모 JS 가 `iframe.contentDocument` 에 직접 손을 댄다(캔버스에 스크립트를 넣지 않는다).
     표시용 CSS 는 `<link>` 로 넣는다(공개 CSP `style-src 'self'`).
   - 바꿀 때마다 초안으로 `POST frame` → 받은 HTML 의 `body` 만 바꿔 끼운다(스크롤이 그대로, 깜빡임 없음).
   - 끌어다 놓기는 포인터 이벤트로 직접 한다(HTML5 끌기는 iframe 경계에서 브라우저마다 다르다).
   - 설정 칸은 admin-ui.js 의 `Form` 을 `window.MaruForm` 으로 꺼내 쓴다.
4. **발행** `POST /admin/editor/publish` (JSON `{ screen, widgets }`)
   - 서버가 지금 DB 와 초안을 견주어 연산을 만든다: 새 블록 → `widget.place`, 바뀐 칸 → `widget.configure`
     (바뀐 칸만), 없어진 블록 → `widget.remove`. 순서가 바뀐 자리는 그 자리 전체를 0,10,20… 으로 다시 매긴다.
   - `changesets::create` + `apply` 로 「화면 편집: 첫 화면」 묶음 하나. 결과로 묶음 주소를 돌려준다.
   - 고친 것이 없으면 묶음을 만들지 않는다. 묶음을 만든 뒤 적용이 실패하면 묶음 화면에서 까닭을 본다.

## 5. 범위 규칙

- 새 블록의 기본 범위는 지금 화면(첫 화면 → `home`, 페이지 → `page:<주소>`, 게시판 → `board:<주소>`).
- 「모든 화면」 블록을 고르면 판에 「여러 화면에 함께 보임」 표시. 고치면 모든 화면에 바뀐다고 알린다.
- 순서: 한 자리의 위젯 순서는 모든 범위가 함께 쓴다. 화면에 보이는 것끼리 순서를 바꾸면, 전체 목록에서
  그 블록들이 차지하던 자리 안에서만 바꾼다(다른 화면 블록의 앞뒤는 그대로).
- 숨기기 = `enabled: false`(지우지 않음). 층 판에서 흐리게 보이고 눈 단추로 되살린다.
- 팝업 블록은 팝업 자리에만 간다(`check_pair`). 광고 자리(후원 띠·양옆·아래 고정·사이트 이름 옆)는 층 판에서만 옮긴다.

## 6. 테스트

- e2e(실제 바이너리): 편집기 화면이 뜬다 / 로그인 안 하면 로그인으로 / 캔버스 GET 에 `data-maru-w` 가 있다 /
  캔버스 POST 초안의 새 블록 글이 그려지고 DB 는 그대로다 / CSRF 없으면 403 / 발행하면 변경 묶음이 적용돼
  공개 화면에 보이고, 되돌리면 사라진다 / 순서 바꾸기·숨기기·지우기가 발행 뒤 DB 에 남는다.
- 단위: 초안 → 연산 만들기(새·고침·지움·순서), 같은 초안 두 번 발행은 두 번째에 할 일 없음.
- 브라우저: 끌어다 놓기·고르기·설정 고치기·기기 전환·되돌리기·발행 뒤 공개 화면.
