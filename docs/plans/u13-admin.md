# 단위 13 관리 화면 전체 — 계획 (S14 · S6 · S4 · M4)

> GAP S4(관리 화면: 게시판·메뉴·페이지·회원·설정·디자인), S6(백업·복원), M4(역할별 게시판 권한 화면), S14(감사 로그 보기).
> 서비스는 대부분 이미 있다(boards·pages·menus·members·settings·design). 이 단위는 사람이 클릭하는 화면과 빠진 경로(감사 조회, 백업)를 채운다.
> 크기가 커서 커밋 셋으로 나눈다: 13a 감사 로그 → 13b 백업·복원 → 13c 관리 화면(S4·M4).

## 1. 결정 (추천안 채택)

| # | 결정 | 추천안(채택) | 대안 |
|---|---|---|---|
| D1 | 감사 로그 읽기 권한 | `site.admin`(운영자·소유자). 에이전트 토큰은 못 본다(SPEC MCP 툴 목록에 없음). CLI 는 로컬 운영자 | 모든 편집자 — 남의 회원 관리 기록까지 보인다 |
| D2 | 감사 조회 조건 | 행위자(`actor_type`·`actor_id`), 동작 앞부분(`post.` 처럼), 대상(`target_type`·`target_id`), 기간(`since`·`until`), 최신 순 페이지 50개. `diff` 는 그대로(이미 비밀 값이 지워져 들어온다) | 전문 검색 |
| D3 | 백업 형식 | `.tar.gz` 하나: `manifest.json`(만든 시각·Maru 버전·스키마 버전·비밀 포함 여부), `maru.db`(`VACUUM INTO` — 서버가 켜져 있어도 일관된 사본), `media/`, `themes/`, `config.toml`. 새 의존성 `tar`·`flate2`(MIT/Apache) | 폴더 복사 — 내려받기·옮기기 불편. zip — 같은 이유로 두 크레이트 |
| D4 | 비밀 빼기 | `--no-secrets`: 사본 DB 에서 세션·로그인 링크·토큰·비밀번호 해시·보낼 편지함을 지운다(SPEC §12). 기본은 전부 포함(그대로 되살리기용) | |
| D5 | 복원 | CLI 전용 `maru restore <파일> --yes`. 서버가 꺼져 있어야 한다: `serve` 가 데이터 디렉터리의 `serve.lock` 을 잡고 있고(`File::try_lock`, 새 의존성 없음), 복원은 같은 잠금을 못 잡으면 「서버를 먼저 끄세요」로 멈춘다. 지금 데이터는 `backups/before-restore-<시각>/` 로 옮긴 뒤 푼다. 스키마가 더 새 백업은 거부, 더 옛것은 풀고 마이그레이션. 관리 화면은 복원 명령을 안내만 한다 | 화면에서 복원 — 켜진 서버의 DB 를 바꿔치기해야 한다 |
| D6 | 백업 화면 | `/admin/backups`: 목록(크기·시각·비밀 포함), 「지금 백업」(비밀 포함/제외), 내려받기, 지우기. `site.admin` | |
| D7 | 관리 화면 | 게시판(목록·만들기·고치기: 이름·형태·정책·여분 필드 JSON·목록 순서·정렬, 지우기), 페이지(목록·만들기·고치기·발행·숨기기), 메뉴(위치별 항목 편집), 회원(목록·역할·사용 중지), 설정(사이트 설정 폼), 디자인(토큰 폼·되돌리기). 전부 기존 서비스 호출, 실패하면 값 유지 + 오류 | |
| D8 | M4 | 게시판 폼의 정책 칸(읽기·쓰기·댓글·업로드·관리 서열)을 역할 선택 목록으로. 서비스는 이미 `BoardPolicy` | 역할마다 게시판 표 — 서비스가 없다 |

## 2. 다섯 경로

- 13a: core `audit::list`(+ store `list_audit`), REST `GET /api/v1/audit`, CLI `maru audit list`, 화면 `/admin/audit`.
- 13b: core `backup` 서비스(바이너리 쪽 파일 작업은 storage), CLI `maru backup [--out] [--no-secrets]`·`maru backup list`·`maru restore`, REST `POST /api/v1/backups`·`GET /api/v1/backups`, 화면 `/admin/backups`.
- 13c: 화면만(서비스·REST·CLI 는 있음).

## 3. 작업 단위

| 단위 | 내용 | 테스트 |
|---|---|---|
| 13a | 감사 조회 | 저장소: 조건·순서·페이지·권한. e2e: 글 쓰고 `maru audit list --action post.` |
| 13b | 백업·복원 | 저장소: VACUUM INTO 사본·비밀 빼기. e2e: 서버 켠 채 백업 → 글 지움 → 서버 끄고 복원 → 글 돌아옴, 켜진 서버면 복원 거부 |
| 13c | 관리 화면 | e2e: 각 폼 POST → DB 확인(게시판 정책·페이지 발행·메뉴·회원 역할·설정·토큰), 브라우저 데스크톱·모바일 |

완료 기준: 운영자가 CLI 없이 관리 화면에서 사이트 구조·회원·설정·디자인을 고치고, 감사 로그로 누가 무엇을 했는지 보고, 백업을 만들어 내려받을 수 있다.
