# 사이트 종류(테마) 넓히기 계획 (ADR-0139)

> 관리 화면의 「테마」는 사이트 종류다(ADR-0137). 지금 12개(커뮤니티·블로그·회사·가게·기관·랜딩·포트폴리오·
> 매거진·강의·행사·채용·문서)에 한국에서 흔히 만드는 사이트 종류 10개를 더한다.
> 프리셋 파일(`crates/themes/builtin/presets/*.toml`)만 더하므로 CLI `maru init --preset`, MCP
> `create_site_from_preset`·`apply_theme`, 관리 화면 테마 카드가 함께 쓴다.

## 1. 벤치마킹 원칙

- 업종마다 사이트들이 공통으로 갖는 **구조**(메뉴 구성, 첫 화면 섹션 순서, 게시판 종류, 목록에 보이는 칸, 문의 흐름)만
  본다. 특정 사이트의 코드·이미지·문구·색은 옮기지 않는다(CLAUDE.md 원칙 7). 색과 모양은 우리 토큰으로 새로 정한다.
- 예시 글은 「무엇을 적을지」 안내하는 말로 쓴다. 지어낸 상호·인물·후기·수치를 사실처럼 쓰지 않는다
  (숫자 자리는 `00`, 상호 자리는 「가게 이름」).
- 업종 법규가 화면 구성에 닿는 곳은 구조에 반영한다. 법률 판단은 아니고, 운영자가 확인할 자리를 남기는 것이다.
  - 병원·의원: 의료법 제56조와 시행령 제23조는 환자 치료경험담 등 치료 효과를 오인하게 할 광고를 금지하고,
    로그인 같은 제한 없이 공개 게시하는 후기를 문제로 본다 → **후기 블록·후기 게시판을 두지 않는다.** 상담 게시판은 비밀글.
  - 쇼핑몰(통신판매): 상호·대표자·주소·전화·사업자등록번호·통신판매업 신고번호를 쉽게 볼 수 있게 표시하는 것이
    실무 기준 → 바닥글에 사업자 정보 자리를 둔다.
  - 부동산 중개: 공인중개사법 제18조의2와 국토교통부 고시가 표시·광고 명시사항을 정한다 → 바닥글에 중개사무소 정보
    자리, 매물 칸에 소재지·면적·가격·거래 종류·층·사용승인일·방향을 둔다. 정확한 항목은 운영자가 최신 고시로 확인한다.

## 2. 업종별 구조 분석과 결정

| 종류 (id) | 흔한 구조 | Maru 구성 |
|---|---|---|
| 쇼핑몰 진열형 (`shop`) | 큰 배너 → 카테고리 → 새 상품·베스트 바둑판 → 혜택(배송·교환) → 후기 → 공지·고객센터. 상품 상세는 사진·가격·옵션·구매 단추 | `products` 사진형 게시판(분류·가격·품절·구매 링크 칸), `reviews` 후기 게시판(회원 쓰기), 공지, 「주문·배송 안내」, 「문의」 폼, 바닥글 사업자 정보. 결제·장바구니는 SPEC 범위 밖이라 구매 링크(외부 스토어)나 문의로 받는다 |
| 중개·디렉터리 플랫폼 (`platform`) | 검색창이 있는 큰 배너 → 분야 바로가기 → 이용 방법 3단계 → 등록된 업체·전문가 카드 → 최근 요청 → 입점 안내 | `listings` 카드형 게시판(분야·지역 거르기, 연락처·누리집 칸), `requests` 요청 게시판(회원 쓰기, 채택), 공지, 「이용 안내」, 「입점 신청」 폼 |
| 병원·의원 (`clinic`) | 진료 안내·예약 전화가 첫 화면 위 → 진료과목 → 의료진 → 진료시간 → 공지 → 오시는 길. 메뉴: 병원 소개·의료진·진료 안내·커뮤니티 | 「병원 소개」(의료진·장비), 「진료 안내」(진료과목·진료시간·비급여 안내 자리), 공지, 건강 정보(웹진형), 온라인 상담(질문형·비밀글), 오시는 길. 후기 없음 |
| 학원·교습소 (`academy`) | 강좌·반 안내 → 시간표 → 강사 소개 → 공지·학부모 안내 → 상담 신청 | 「강좌 안내」(반별 대상·수강료 표), 「강사 소개」, 시간표(영업시간 블록을 반·요일 표로), 공지, 수강 후기(회원 쓰기), 「상담 신청」 폼. 온라인 강의 노트는 `course` 몫 |
| 숙박·펜션 (`stay`) | 큰 사진 → 객실 카드 → 시설·즐길 거리 → 요금표(비수기·성수기) → 이용 안내(입실·퇴실·환불) → 예약 문의 → 오시는 길 | `rooms` 사진형 게시판(기준·최대 인원, 크기, 요금 칸), 시설 소개, 요금표, 이용 안내 질문, 「예약 문의」 폼, 여행 후기(회원 쓰기), 오시는 길 |
| 부동산 중개 (`realty`) | 매물 검색·거래 종류 탭 → 추천 매물 카드 → 중개사 소개 → 매물 접수·문의 → 오시는 길 | `listings` 카드형 게시판(거래 종류·매물 종류 거르기, 거래 완료 표시, 명시사항 칸), 「매물 내놓기·문의」 폼, 중개사 소개, 바닥글 중개사무소 정보 |
| 교회·종교 단체 (`church`) | 예배·모임 시간 → 주보·설교(말씀) → 교회 소식 → 섬기는 분들 → 새가족 안내 → 오시는 길 | 말씀(웹진형), 주보·자료(자료실), 교회 소식(사진형), 「교회 소개」(섬기는 분들·연혁), 「새가족 안내」 폼, 예배 시간표, 오시는 길 |
| 동호회·모임 (`club`) | 모임 소개 → 다가오는 모임 일정 → 활동 사진 → 가입 인사 → 회칙·회비 → 가입 신청 | 모임 일정 카드형(모임일·장소·참가비 칸, 마감일 거르기), 활동 사진, 가입 인사, 회원 게시판(회원만 읽기), 「모임 안내」(회칙·회비), 「가입 신청」 폼 |
| 링크 모음 (`linkbio`) | 한 장: 프로필 → 큰 단추 링크 줄 → 최근 소식 → 연락 | 첫 화면 하나: 큰 글자 소개, 링크 줄(행 목록), 최근 소식, 연락 안내. 게시판은 소식 하나 |
| 전문 사무소 (`office`) | 업무 분야 → 왜 우리인가 → 구성원 → 상담 절차 → 칼럼·소식 → 상담 신청. 법률·세무·노무·회계 | 「업무 분야」, 「구성원 소개」, 칼럼(블로그형), 소식, 「상담 신청」 폼(분야 고르기). 승소율 같은 성과 숫자는 두지 않는다(광고 규정이 있는 직역이 많다) |

이미 있는 종류와 겹치는 것(카페·식당·미용실 → 가게, 관공서·학교·협회 → 기관·단체, 온라인 강의 → 강의,
기술 문서·위키 → 문서, 웹진·뉴스 → 매거진)은 더하지 않는다.

## 3. 만드는 것

- 프리셋 10개. 연산은 모두 「없으면 만든다」라 기존 사이트에 골라도 지우지 않는다(ADR-0137).
- 관리 화면 테마 카드: 「이런 사이트에」 한 줄과 견본 그림(SVG 속성만, 관리 CSP).
- CLI·MCP: 프리셋 목록은 파일에서 읽으므로 바뀔 것 없다. `AGENTS.md`·`llms.txt` 의 목록을 고친다.
- 테스트: `e2e_site_types` 의 전 종류 반복(첫 화면 200·h1 하나·섹션·모든 링크 살아 있음·두 번 실행해도 같음)에 10개를 더한다.
  폼 블록은 받은 내용이 DB 에 남는지, 게시판 칸 거르기가 되는지 몇 종류에서 본다.
