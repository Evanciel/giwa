# 단위 11b — 글 이동·복사·일괄 관리, 리비전 비교·되돌리기 (GAP C11·C12)

> 2026-11-04. 결정 표는 추천안으로 진행(사용자 지시). 리비전은 지금 저장만 되고 어느 경로로도 보이지 않는다.

## 1. 결정

| # | 결정 | 추천안(채택) | 대안 |
|---|---|---|---|
| D1 | 비교 | core `diff` 모듈: 줄 단위 LCS(같음·더함·뺌), 양쪽 곱이 400만 줄을 넘으면 「통째로 바뀜」 한 덩어리. 제목은 따로 비교. 새 의존성 없음 | `similar` 크레이트 — 의존성 추가를 물어야 하고, 글 본문 크기에선 직접 구현으로 충분 |
| D2 | 되돌리기 | `posts::revert(id, revision)`: 그 리비전의 제목·본문으로 고친다. 권한·상태 규칙은 `update` 와 같고(지운 글 거부), 새 리비전이 하나 더 쌓인다. 감사 `post.revert`(diff 에 어느 리비전인지) | 리비전 지우고 되감기 — 기록이 사라진다 |
| D3 | 이동 | `posts::move_to(id, board, category?)`: 원래 게시판에서 고칠 권한 + 새 게시판 쓰기 권한(정책 `write`·게시판 범위). 분류는 새 게시판 것만(없으면 비움), 슬러그가 겹치면 `-2` 를 붙인다. 댓글·조회수·리비전은 글을 따라간다. 감사 `post.move` | 지우고 새로 쓰기 — 주소·댓글이 끊긴다 |
| D4 | 복사 | `posts::copy_to(id, board)`: 새 게시판에 **초안**으로(제목·본문·요약·대표 그림·태그). 글쓴이는 복사한 사람, 댓글·조회수는 가져가지 않는다. 감사 `post.copy` | 상태까지 복사 — 발행 권한 없이 공개 글이 생긴다 |
| D5 | 일괄 | `posts::bulk(ids ≤ 100, action)`: `publish`·`hide`·`delete`·`restore`·`move{board}`. 글마다 기존 서비스를 따로(각자 트랜잭션) 부르고 `[{id, ok, error}]` 로 돌려준다 — 일부만 되는 것이 정상이다(권한·상태가 글마다 다르다) | 한 트랜잭션 — 하나만 막혀도 전부 실패해 100개 중 무엇이 문제인지 알기 어렵다 |
| D6 | 화면 | 관리 글 편집기에 「리비전」 링크 → `/admin/posts/{id}/revisions`(목록, 고른 리비전과 지금 본문 비교, 되돌리기 단추). 관리 글 목록에 고르기 칸 + 일괄 동작 + 옮길 게시판. 편집기에 「다른 게시판으로 옮기기·복사」 | |

## 2. 다섯 경로

- **REST**: `GET /posts/{id}/revisions`, `GET /posts/{id}/revisions/{rid}`(비교 포함), `POST /posts/{id}/revisions/{rid}/revert`, `POST /posts/{id}/move`, `POST /posts/{id}/copy`, `POST /posts/bulk`.
- **CLI**: `maru post revisions <id>`, `maru post diff <id> <rid>`, `maru post revert <id> <rid>`, `maru post move <id> --board <b> [--category <c>]`, `maru post copy <id> --board <b>`, `maru post bulk <action> --id … [--board]`.
- **관리 화면**: D6.
- **MCP**: Phase 3.

## 3. 작업 단위

| 단위 | 내용 | 테스트 |
|---|---|---|
| T1 | core `diff` | 단위: 같음·더함·뺌·빈 글·큰 입력 |
| T2 | `revert`·`revision`·`compare` | 저장소: 되돌리면 본문이 옛것, 리비전 +1, 남의 글 거부, 다른 글의 리비전 거부, 감사 |
| T3 | `move_to`·`copy_to`·`bulk` | 저장소: 이동 후 board_id·분류 비움·슬러그 겹침, 새 게시판 쓰기 권한 없으면 거부, 복사는 초안·글쓴이, 일괄 일부 성공 |
| T4 | REST·CLI | e2e: CLI 되돌리기 → DB, 이동 → 공개 주소 바뀜, 일괄 숨김 |
| T5 | 관리 화면 | e2e: 리비전 화면 비교 표시, 되돌리기 POST → DB, 목록 일괄 동작 |
| T6 | 브라우저, ADR-0055, GAP | 게이트 |

완료 기준: 관리 화면 리비전 화면에서 옛 리비전을 「되돌리기」 하면 DB `posts.body_md` 가 그 리비전 본문이 되고, 관리 글 목록에서 글 둘을 골라 다른 게시판으로 옮기면 두 글의 `board_id` 가 바뀐다.

## 진행 (2026-11-04)

- T1~T6 완료. ADR-0055.
- 계획과 다르게: 되돌리기는 리비전을 읽기 풀에서 찾는다(쓰기 트랜잭션 트레이트에 리비전 조회가 없고, 리비전은 쌓기만 한다). 관리 화면 이동·복사는 편집기 한 폼의 단추 둘(`how=move|copy`).
- 브라우저(데스크톱·375px): 데모 글 본문 고침 → 리비전 2개, 「지금」 바로 앞 것과 비교(+3 −0) → 되돌리기 → 「리비전으로 되돌렸습니다」, 편집기에 리비전 보기·옮기기·복사, 글 목록 고르기 칸·일괄 바. 가로 넘침 없음.
