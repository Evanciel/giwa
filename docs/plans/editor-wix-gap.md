# 화면 편집기 Wix 격차 메우기 계획

> 2026-11-10. `visual-editor.md`(ADR-0138~0146) 다음 단계. 목표: 처음 온 사람이 설명서 없이
> 첫 화면을 꾸미고, 그림을 바꾸고, 페이지를 더하고, 모듈 블록을 넣어 발행할 수 있게 한다.
> 모든 변경은 지금처럼 발행 한 번 = 변경 묶음 하나 = 한 번에 되돌리기(원칙 4)를 지킨다.

## 1. 지금 되는 것과 모자란 것

| Wix 에서 사람이 하는 일 | 지금 | 모자란 점 |
|---|---|---|
| 블록 끌어다 놓기·순서·복제·숨기기·지우기 | 된다 | — |
| 층 판·되돌리기·기기 전환·기기별 숨기기 | 된다 | — |
| 글자 그 자리에서 고치기, 사이트 이름·메뉴 | 된다 (ADR-0144·0145) | — |
| 그림을 눌러 바꾸기 | 오른쪽 판 칸에서 새로 올리기만 | 캔버스에서 못 누른다. 올려 둔 그림을 다시 고르지 못한다 |
| 단추·링크 대상 고르기 | 주소를 손으로 친다 | 페이지·게시판 목록에서 고르지 못한다 |
| 블록 꾸미기(배경·여백·정렬·모양) | 띠 색(tone)·모양(style)이 설정 칸 글자 목록에 묻혀 있다 | 보이는 칩으로 못 고른다. 여백·정렬이 없다 |
| 사이트 색·글꼴 | `/admin/design` 따로 | 편집기 안에서 바꿔 보며 못 고른다 |
| 새 페이지 만들기 | `/admin/pages` 따로 | 편집기 안에서 못 만든다. 빈 페이지만 |
| 앱(모듈) 더하기 | `/admin/modules` 에서 켜야 블록이 보인다 | 꺼진 모듈 블록은 판에 없다 |
| 다른 PC 에서 이어 고치기 | 이 브라우저 localStorage 만 | 서버에 초안이 없다 |
| 처음 안내 | 없다 | 빈 화면·첫 방문에 무엇을 할지 모른다 |

일부러 하지 않는 것: 픽셀 자유 배치(ADR-0138 그대로), 블록별 임의 색 코드(토큰 밖 색은 대비·일관성을
깬다 — 칩은 테마 토큰 안에서만 고른다), 애니메이션 편집.

## 2. 작업 단위 (순서대로, 단위마다 ADR·게이트 커밋·미니PC 배포)

### E1 그림·링크 고르기 (ADR-0147)

- 캔버스: 테마가 그림 칸에 `data-maru-f="image"`(경로) 와 `data-maru-img` 를 붙인다(편집 중일 때만, ADR-0144 의
  `edit_field` 를 그림용 `edit_image` 로 넓힘). 고른 블록의 그림을 누르면 **그림 판**이 열린다.
- 그림 판: 올려 둔 그림 격자(`media::list`, 최근순·쪽 넘김), 「새로 올리기」 단추와 판 위로 끌어 놓기 올리기,
  그림 설명(alt) 칸 — 비우면 발행 전 확인 목록에 「그림 설명 없음」으로 남는다. 고르면 초안의 그 칸이 바뀐다.
- 오른쪽 판의 그림 칸도 같은 그림 판을 연다(admin-ui.js `Form.upload` 를 「고르기·올리기」로).
- 링크 고르기: 링크 칸(`link`, 단추 주소)에 「고르기」 → 공개 페이지·게시판·첫 화면 목록 + 「바깥 주소」 칸.
  글자 바로 고치기에서 단추를 고르면 떠 있는 막대에 「링크」 단추.
- 서버: 관리 쿠키 세션용 `GET /admin/editor/media?cursor=` (JSON, 디자인 권한). 서비스는 `media::list` 그대로.
  REST(`/api/v1/media`)·CLI·MCP 는 이미 있다.
- 테스트: e2e — 캔버스 그림에 표시가 붙는다 / 공개 화면엔 없다 / 그림 목록 JSON 은 로그인 없으면 거절 /
  그림을 바꾼 초안 발행 → DB 설정의 image 가 바뀐다. 브라우저 — 누르기·고르기·올리기·alt.

### E2 블록 꾸미기와 사이트 디자인 (ADR-0148)

- 섹션 공통 설정에 `space`(`tight`·`normal`·`roomy`, 기본 normal)와 `align`(`start`·`center`) 추가.
  `sections.rs` 검증, 두 테마 CSS 에 `.space-*`·`.align-*`(토큰 간격만 씀). 기존 설정은 기본값이라 그대로 보인다.
- 오른쪽 판을 「내용 / 꾸미기」 두 탭으로. 꾸미기 탭: 띠 색 3칩(바탕·옅은 면·주 색, 실제 토큰 색으로 칠함),
  모양 칩(hero 3·features 5 등 `*_STYLES` 를 작은 도식 그림으로), 여백 3칩, 정렬 2칩.
- 「사이트 디자인」 판(층 판 옆 세 번째 탭): 주 색·글꼴·모서리 둥글기를 고르면 캔버스에 바로 보이고,
  발행 때 같은 묶음에 `tokens.set` 연산으로 들어간다(디자인 화면과 같은 `design::update` 검증).
  초안 토큰은 캔버스 POST 에 실어 `task_local` 로 건넨다(ADR-0145 의 사이트 초안과 같은 길).
- 서비스: 위젯 설정·토큰 둘 다 기존 서비스라 REST·CLI·MCP 가 자동으로 같다(`widget configure --config`).
- 테스트: 단위 — space·align 검증, 모르는 값 거절. e2e — 초안 토큰이 캔버스에만 보이고 DB 는 그대로 /
  발행하면 tokens.set 이 묶음에 들고 되돌리면 원래 색.

### E3 편집기에서 페이지 만들기 (ADR-0149)

- 위 막대 화면 고르기 아래 「+ 새 페이지」: 이름 → 주소 자동 제안(바꿀 수 있음), 틀 고르기
  (빈 페이지·회사 소개·서비스 소개·연락처 — 섹션 블록 묶음), 「위 메뉴에 넣기」 체크.
- 만들기 누르면 `pages::create` 로 **초안 상태 페이지**를 바로 만든다(공개 안 됨, 감사 기록). 편집기는 그 화면으로
  넘어가고 틀의 블록은 초안 위젯으로 들어간다. 발행하면 묶음에 `page.publish` + 블록 `widget.place` +
  (체크했으면) `menu.set`. 묶음을 되돌리면 페이지는 다시 초안, 블록·메뉴도 원래대로.
- 발행 안 하고 나가면 초안 페이지는 `/admin/pages` 초안 목록에 남는다(지우기는 거기서).
- 틀은 `crates/themes` 의 JSON(섹션 종류·기본 내용)으로 두고 CLI `maru page create --layout <틀>` 와 MCP 툴에서도
  같은 틀을 고른다. CLI 는 지금의 `maru page new` 에 `--layout <틀>` 을 더한다
(새 기능 순서: core 서비스 `pages::layouts` → REST → CLI → MCP).
- 테스트: e2e — 편집기에서 만든 페이지는 공개 404 / 발행 뒤 200·메뉴에 보임 / 되돌리면 다시 404.
  `maru page new --layout` 멱등.

### E4 앱 블록을 편집기에서 켜기 (ADR-0150)

- 더하기 판 맨 아래 「앱 더하기」 묶음: 꺼진 모듈이 주는 블록(지도·문의 양식·투표 등)을 흐린 카드로.
  누르면 「○○ 앱을 켜고 블록을 넣을까요?」 → 켜기는 그 자리에서 `modules::enable`(모듈 관리 권한 있는 사람만,
  없으면 카드에 「관리자에게 요청」). 켠 뒤 종류 목록을 다시 받아 블록을 초안에 넣는다.
- 켜기를 발행 묶음에 넣지 않는 까닭: 모듈 마이그레이션·라우트가 켜져야 캔버스가 그 블록을 그릴 수 있다.
  ADR 에 대안(발행 때 module.enable)과 함께 적는다. 켜기는 감사 기록에 남고 `/admin/modules` 에서 끈다.
- 테스트: e2e — 꺼진 모듈 블록이 kinds 에 `off: true` 로 온다 / 권한 없는 사람은 켜지 못한다 / 켠 뒤 블록 발행.

### E5 초안을 서버에 (ADR-0151)

- 새 표 `editor_drafts(user_id, screen, body, base, updated_at)` + 마이그레이션(up·down). 서비스
  `editor_drafts::{get, save, discard}`(본인 것만, 크기 한도 512KB).
- 편집기는 고칠 때마다 2초 묶어 저장(지금 localStorage 자리를 서버로, 서버가 안 되면 localStorage 로 물러남).
  다시 열면 「다른 기기에서 고친 초안이 있습니다(시각)」 → 이어서/버리기. 발행하면 지운다.
- `base` 가 지금 DB 와 다르면(그 사이 누가 발행) 이어 고칠 때 「그 사이 바뀐 곳이 있습니다」 경고 — 지금
  localStorage 의 hash 규칙 그대로.
- REST `/api/v1/editor/drafts/{screen}` 도 같은 서비스(에이전트가 사람의 초안을 읽어 거들 수 있게). CLI·MCP 는
  필요가 확인되면 더한다고 ADR 에 적는다.
- 테스트: storage 단위(덮어쓰기·본인만·한도), e2e(저장→다른 쿠키 세션 같은 사용자에서 읽힘→발행 뒤 사라짐).

### E6 처음 안내와 빈 화면 (ADR-0152)

- 첫 방문(서버 초안·사용자 설정에 「봤음」 기록) 4걸음 안내: 더하기 판 → 캔버스에 끌기 → 블록 고르고 글자 고치기
  → 발행. 건너뛰기·다시 보기(「?」 단추). 키보드: Esc 닫기, 화살표 다음.
- 빈 화면(본문 블록 0개)이면 캔버스 가운데에 「이 화면에 어울리는 묶음으로 시작」 카드 3개(사이트 종류 프리셋의
  섹션 묶음 재사용) + 「빈 블록부터」.
- 「?」 단추에 단축키 목록(Ctrl+Z·Ctrl+Y·Delete·Ctrl+D 복제·Ctrl+S 초안 저장).
- 테스트: e2e — 빈 화면 캔버스에 시작 카드 / 묶음 고르면 초안에 블록. 브라우저 — 안내 흐름·건너뛰기·다시 보기.

## 3. 마무리 점검 (모든 단위 뒤)

처음 쓰는 사람 과제를 브라우저에서 그대로 해 본다. 설명서 없이 편집기만으로:

1. 빈 사이트에서 첫 화면을 「동네 카페」로 꾸민다(시작 묶음 → 제목·설명 고치기 → 대표 그림 바꾸기).
2. 띠 색·여백을 바꾸고 사이트 주 색을 바꾼다.
3. 「메뉴」 페이지를 새로 만들어 가격표 블록을 넣고 위 메뉴에 단다.
4. 지도 앱을 켜고 오시는 길 블록 옆에 지도 블록을 넣는다.
5. 휴대폰 보기에서 큰 그림 블록을 숨긴다. 발행 → 공개 화면 확인 → 묶음 되돌리기 → 원래대로.
6. 다른 브라우저(다른 쿠키 세션)로 로그인해 고치던 초안을 이어 연다.

각 걸음이 막히는 곳을 적고 고친다. 결과를 이 문서 끝에 표로 남긴다.

## 4. 위험과 대응

| 위험 | 대응 |
|---|---|
| 꾸미기 칩이 테마마다 다르게 보임 | 칩 색을 그 사이트의 실제 토큰 값으로 칠하고, 두 테마(builtin·community) 모두 브라우저 확인 |
| 초안 토큰이 캔버스 밖으로 샘 | task_local 은 캔버스 요청에만. e2e 로 공개 GET 이 DB 값인지 확인 |
| 편집기에서 만든 초안 페이지가 쌓임 | 페이지 목록 초안 표시. 30일 지난 빈 초안 정리는 필요 확인 뒤 |
| 모듈 켜기가 되돌리기 묶음 밖 | 확인 대화에 「앱 켜기는 되돌리기에 들지 않습니다」 명시, ADR 기록 |
| page-editor.js 가 커짐(1,185줄) | E1 에서 그림 판, E2 에서 꾸미기·디자인 판을 별도 파일(`editor-media.js`, `editor-style.js`)로 나눈다 |
